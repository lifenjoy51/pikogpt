  • 드리프트 주제 혼합 — 일부 샘플이 기업/정치 담론으로 급격히 빠짐 ("oil company", "government", "environmental laws"). Conversation 코퍼스에 TV 다큐·뉴스 발췌가 섞인 듯.

개선 방향

1. 데이터 측면 (최우선)

  • 중복 제거 + 반복 제거 — "just keep swimming" 같은 반복 구절이 원본에 그대로 있음. doc 단위 중복 제거 + repetition thresholding (같은 구절이 2회 이상 반복되면 clip).
  • 코퍼스 증량 — 100M conversation만으로는 831k tok에 불과. TinyHelen의 book(1.47MB), textbook(2.17MB)까지 합쳐 다중 장르 혼합해 3M+ tokens로 확장. 샘플 품질은 떨어질 수 있으나 memorization이 희석됨.
  • 외부 대화 코퍼스 병합 — DailyDialog, OpenSubtitles, Cornell Movie-Dialogs 등. 장르 다양성으로 단일 script 암기 방지.
  • 샘플러 단 repetition penalty — 학습은 건드리지 않고 Sampler에서 최근 n토큰 내 동일 토큰 logit 페널티. "just keep swimming" 패턴 차단.

2. 모델·아키텍처

  • Context 확장 — blockSize 64 → 128 or 256. 대화는 long-range turn dependency가 의미의 핵심. 비용 O(block²) 증가이나 attention 병렬화로 감당 가능.
  • Speaker / turn 분리 토큰 — 현재 " " 따옴표만으로 구분. <|speaker1|>, <|turn|> 같은 전용 special token 도입해 발화 경계를 명시적으로 학습시키면 대화 구조 더 빠르게 내재화.
  • 파라미터 수 확대 — 1M은 표현력 명확한 한계. 2-3M (예: layers 6 · dim 160)이면 iter당 1.5-2초로 감당 가능. 과적합은 이미 강한 regularization으로 관리 중.
  • Weight tying — token embedding과 lm_head 공유. 파라미터 13%(136k) 절약 + regularization 효과.

3. 학습 전략

  • Document-level batch sampling — 현재 DataLoader는 글로벌 random offset만 사용. 긴 문서는 많은 window에 포함돼 암기 가속. 문서 단위로 uniform 샘플링 후 문서 내 offset을 잡으면 노출 균등화.
  • Curriculum learning — 짧은 대화(2-3 turn) 먼저 학습 후 긴 대화로 확대. TinyHelen은 문서 길이 다양.
  • Early stopping + patience — val best 후 3회 연속 미갱신이면 종료. 지금은 수동으로 best ckpt 선택 중.
  • Mixed-precision (FP16) — 속도 2× + 일부 regularization 효과. Kotlin FloatArray는 이미 32bit이나 내부 matmul을 Float16 버퍼로 바꾸면 가능.

4. 측정·디버깅

  • 다중 val set — 현재 val도 같은 장르(conversation). out-of-genre val(예: textbook val의 일부 혼합) 추가해 "대화 암기" vs "언어 모델 일반화"를 분리 측정.
  • Token-level 샘플 analysis — 생성된 문장의 n-gram이 train set의 n-gram과 겹치는 비율 자동 측정. 90%+면 암기 경고.
  • Gradient norm 장기 추적 — v3 run에서 grad-norm 0.86→2.33으로 꾸준히 상승. overfitting의 early warning으로 활용 가능.
  • Perplexity 외 metric — BLEU/ROUGE로 샘플-원본 유사도 측정 (이걸 높이려는 게 아니라 memorization 지표로).
