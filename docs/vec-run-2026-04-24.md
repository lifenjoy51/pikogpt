# TinyHelen Vec 백엔드 학습 보고 (2026-04-24)

## 목적

Value 기반 스칼라 autodiff의 성능 한계를 `vec/` 백엔드(FloatArray + 명시 backward)로 돌파한 뒤, 처음으로 **1M 파라미터 모델**을 TinyHelen 코퍼스에 학습시킨 실험의 기록. 이전 71K 스칼라 overnight(7시간, val best 6.23)과의 비교 + 생성 샘플 평가.

## 설정

### 데이터
- `data/tinyhelen/` (book + textbook + wiki + conversation, 각 jsonl line이 `<|bos|>…<|eos|>`로 래핑됨)
- BPE vocab 1000 (special: eos=0, unk=1, bos=2; 895 merges)
- train: 1,485,987 tokens / val: 165,110 tokens

### 모델 (`≈1,055,488` 파라미터)
| 항목 | 값 |
|---|---|
| layers | 4 |
| embedding dim | 128 |
| heads | 4 (head dim 32) |
| FFN hidden | 512 |
| blockSize | 48 |
| dropout | 0.0 (vec 미구현) |

### 옵티마이저 / 스케줄
| 항목 | 값 |
|---|---|
| AdamW β1/β2, wd | 0.9 / 0.95, 0.02 |
| gradClip | 1.0 |
| peak/min LR | 3e-4 / 5e-5 |
| warmupRatio | 0.05 (75 iter) |
| decayRatio | 0.85 (cosine, 1275까지), 이후 min plateau |
| maxIters | 1500 |
| batchSize × accum | 2 × 4 = effective 8 |
| evalInterval | 75 iter, evalIters=4 |

### 실행
```
./gradlew runTinyHelenTrainVec
./gradlew runTinyHelenSampleVec   # 자동으로 최신 ckpt 선택
```
래퍼: `scripts/run-overnight-vec.sh` (train → sample 체인).

## 타이밍

- **총 학습 시간: 24분 50초** (1500 iter, elapsed 1490s)
- **평균 iter당: 0.99초**
- 이전 스칼라 71K overnight: 7시간 (iter당 16초)
- **스피드업: 약 16× (학습 시간), 동일 데이터·스케줄에서 파라미터는 15× 큰 모델**

예측치(30-45분)보다 빠름 — 실제 CPU 단일 스레드로도 1.0s/iter 수준에 수렴함.

### 관찰
1. **이전 스칼라 7시간 run의 best(avg 6.23)를 iter 150(2.5분)에 돌파**. 같은 시간 예산으로 훨씬 더 깊은 학습 가능함을 증명.
2. **val loss 4.65가 이번 best** — 이전 스칼라 대비 2.2 퍼플렉서티 자릿수 차이 (e^6.23 ≈ 509 vs e^4.65 ≈ 105). 어휘 1000 중 대략 100개로 좁힌 예측.
3. **train-val gap 확장 (iter 1200)**: 4.42 vs 4.88 = 0.46 차이. 1 epoch 미만 노출 상황에서 경미한 overfit 조짐이나 val이 계속 내려가고 있었으므로 early stop 불필요.
4. **iter 1275 이후 reversion**: LR이 5e-5로 고정되는 plateau 구간에서 gradient noise가 weights를 최적점에서 밀어냄. 이전 스칼라 run에서도 동일 패턴 관찰됨. **best 체크포인트(iter 1200)가 실질 최적점**.
5. **grad-norm 추세**: 0.0 → 0.85 → 1.2 → 2.9로 상승. clip 1.0에 자주 걸림. LR 더 낮추거나 clip 풀어두는 게 후반 드리프트에 유리할 수 있음.

### 샘플 평가

**잘 배운 것**:
- 영어 단어 경계와 공백 패턴 대체로 정확
- 자주 등장하는 기능어(`the`, `and`, `to`, `of`, `is`, `a`, `for`, `in`, `how`, `what`, `we`, `they`)의 문법적 위치 잡힘
- 형태소 조각 (`-ing`, `-tion`, `-ers`, `-ed`) 빈번하고 대체로 맞는 맥락에 출현
- 구두점 사용 자연 (`.`, `,`, `:`, 개행) 
- BOS/EOS 특수 토큰이 출력에서 필터링됨 (의도대로)

**못 배운 것**:
- 의미 있는 명사구가 거의 없음 — "the rirces", "a pote", "the bor" 같은 **단어가 아닌 토큰**을 만들어냄 (BPE subword가 잘못 합쳐짐)
- 구문 안에서의 긴 거리 의존성 부재 — 문장 전체가 앞뒤가 안 맞음
- 명사·동사 호응 수시로 깨짐

## 이번 run의 교훈

1. **벡터화가 결정적**. 스칼라 구조는 교육적 가치가 있지만 실험용으로는 치명적으로 느림. 벡터 버전에서 처음으로 "의미 있는 학습"까지 도달.
2. **Cosine decay 끝의 min-LR plateau는 위험**. 두 run 모두 최후 15-20% 구간에서 best로부터 0.1-0.2 drift. 체크포인트 저장이 있어서 손실 없지만, 향후에는 decayRatio 1.0으로 돌려 cosine이 끝까지 진행하게 하는 것도 고려.
3. **데이터 노출 부족**. 1 epoch ≈ 3400 iter (= 1,485,987 tokens / (8 × 48 tokens per iter))인데 1500만 돌렸다. **벡터 스피드업으로 이제 2-3 epoch도 overnight(~1-1.5시간)로 가능** — 다음 실험 소재.
4. **CPU 병렬화 여유**. 이 run은 단일 스레드로 돌았으나 병렬 경로(커밋 `1f54dfb`)가 합쳐진 상태라, 다음 run은 ~4-8× 추가 가속 예상 → 같은 1500 iter가 3-6분.

## 병렬 경로 벤치마크 (2026-04-24 후속)

커밋 `1f54dfb` 이후 `vec.Trainer`는 한 iter의 `accum × batch` 시퀀스를
CPU 코어 수만큼의 worker PikoGPT 복제본에 나눠 `Dispatchers.Default`로
동시 실행한다. 매 iter 시작에 worker ← master 파라미터 data sync,
끝에 worker → master grad accumulate.

12-core 머신에서 실측 (50 iter, 같은 recipe A config):

| 지표 | Sequential | **Parallel** | 스피드업 |
|---|---|---|---|
| worker 수 | 1 | **8** (seq/iter = batch 2 × accum 4) | — |
| iter당 | 1.0s | **0.52s** | **1.92×** |
| 1500 iter 예상 | 25분 | **≈13분** | — |

8-way 병렬인데 실제 2× 밖에 못 얻은 이유 (추정):
- 8 worker가 동시에 1M 파라미터 data를 read → DRAM 대역폭 경합
- 매 iter worker↔master sync + merge 비용 (4MB × 2 × 8 = 64MB 메모리 이동/iter)
- 8× 할당률에서 JVM GC 압력 증가
- coroutine/thread 스케줄링 잔잔 비용

실질적으로는 다음 run을 overnight 걱정 없이 **점심시간에** 돌릴 수 있다는 의미.
SIMD(`jdk.incubator.vector`)나 matmul 블로킹 재작성이 추가 2-4× 여지.

## 후속 실험 아이디어

- **다음 run**: maxIters를 3000-4500으로 확장 (1-2 epoch 이상 노출). 병렬 13분/1500iter 기준 **30-40분 내 가능**.
- **early stopping**: patience 기반으로 iter 1200 근처에서 종료 — drift 회피.
- **LR schedule 튜닝**: decayRatio 0.85 → 1.0 재검토, 또는 cosine-with-restarts 실험.
- **더 긴 blockSize**: 48 → 128. attention 비용 O(block²) 증가하지만 벡터 + 병렬이라 감당 가능. 장거리 의존성 학습 기회 증가.
- **SIMD**: `jdk.incubator.vector.FloatVector` 도입으로 matmul 루프 벡터화. 추가 4-16× 예상 (외부 의존 없이 JDK만).
